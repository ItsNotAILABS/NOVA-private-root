# Orchestration Model — NOVA ORCHESTRA

NOVA ORCHESTRA coordinates specialized model family members into one operating system.

## Mission

Route tasks across CODEX, TASK, CREATIO, SENSUS, CORPUS, VOX, MATHESIS, TEST/BENC, SACE/LAWX, and PORT without losing state or violating boundaries.

## Coordination cycle

1. Ingest objective.
2. Read state and active receipts.
3. Select owner model.
4. Define action and acceptance condition.
5. Execute through approved runtime surface.
6. Write receipt.
7. Re-evaluate unresolved tension.

## Routing examples

- Repository change -> CODEX.
- App generation -> CREATIO + CORPUS.
- Browser/page work -> SENSUS.
- Proof/test concern -> MATHESIS + TEST/BENC.
- Release packaging -> PORT.
- Operator conversation -> VOX.
- Policy/permission concern -> SACE/LAWX.

## Commercial-grade requirements

ORCHESTRA must preserve traceability. Delegation without receipts is not a completed operation. Routing without acceptance criteria is not a valid plan.
