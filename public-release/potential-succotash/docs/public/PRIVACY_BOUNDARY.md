# Privacy Boundary

Sonic Ninja should be described publicly as a local-first browser intelligence workspace. Local-first means core workflows are designed to run on the user's machine where possible. It does not mean every optional integration is automatically offline or private.

## Public-Safe Privacy Language

Approved:

- Core browser workflows are designed for local-first use.
- Offline AI modes can run locally after model setup when available.
- User notes, highlights, and memory features should be documented with storage behavior.
- Optional online connectors should be treated separately and disclosed clearly.

Avoid:

- Absolute statements that no data ever leaves the device unless every integration is verified.
- Claims of third-party privacy certification without evidence.
- Claims that optional cloud, worker, or API features are local-only.

## User Controls to Document

- How to clear saved highlights.
- How to clear notes or memory entries.
- How to disable optional connectors.
- How to export or delete user-created data.
- How to distinguish offline AI flows from online connector flows.

## Release Requirement

Every public release should include a privacy note that separates local extension behavior from optional remote integrations.
